# cfqu

A small TypeScript library that routes Cloudflare Workers queue events by queue name.

## Usage

### Queue-only Worker

```ts
import { Qu } from "cfqu";

const qu = new Qu<Env>();

qu.on("jobs", (batch) => {
  for (const message of batch.messages) {
    console.log("Received:", message.body);
  }
});

export default qu;
```

`Env` is the bindings type generated by `npx wrangler types` from your application's Wrangler configuration.

### Using with Hono

Install `hono` alongside `cfqu`. The same Worker can use Hono for HTTP requests and `Qu` for queue events:

```ts
import { Hono } from "hono";
import { Qu } from "cfqu";

const hono = new Hono<{ Bindings: Env }>();
const qu = new Qu<Env>();

hono.post("/", async (c) => {
  await c.env.JOB_QUEUE.send(await c.req.json());
  return c.text("Accepted", 202);
});

qu.on("jobs", (batch) => {
  for (const message of batch.messages) {
    console.log("Received:", message.body);
  }
});

export default {
  fetch: hono.fetch,
  queue: qu.queue,
} satisfies ExportedHandler<Env>;
```

### Routing behavior

- `on(name, handler)` returns the instance so registrations can be chained.
- Queue names use exact, case-sensitive matching. Use the name in `queues.consumers[].queue` in your Wrangler configuration.
- Registering the same name again replaces the previous handler.
- Handlers receive the original `batch`, `env`, and `ctx` arguments. Asynchronous handlers are awaited.
- Unregistered queues throw `Unknown queue: <queue name>`. Handler errors propagate to the caller.
- Message acknowledgement and retries follow Cloudflare Queues defaults. Call ack or retry methods in your handler when needed.

The package includes ESM and TypeScript declarations. Cloudflare Workers is the only supported runtime.

## Send and receive in one Worker

This example sends and receives messages in a single Worker.

### 1. Set up a project

```sh
mkdir cfqu-example
cd cfqu-example
npm init -y
npm install cfqu
npm install --save-dev wrangler typescript
```

Create `wrangler.jsonc`:

```jsonc
{
  "name": "cfqu-example",
  "main": "index.ts",
  "compatibility_date": "2026-10-15",
  "queues": {
    "producers": [{ "binding": "JOB_QUEUE", "queue": "jobs" }],
    "consumers": [{ "queue": "jobs" }]
  }
}
```

### 2. Add the Worker

Create `index.ts`:

```ts
import { Qu } from "cfqu";

const qu = new Qu<Env>();

qu.on("jobs", (batch) => {
  for (const message of batch.messages) {
    console.log("Received:", message.body);
  }
});

export default {
  async fetch(request, env) {
    await env.JOB_QUEUE.send(await request.json());
    return new Response("Accepted", { status: 202 });
  },
  queue: qu.queue,
} satisfies ExportedHandler<Env>;
```

Generate `Env` and Workers runtime types from your Wrangler configuration:

```sh
npx wrangler types
```

### 3. Send and receive locally

```sh
npx wrangler dev
```

In another terminal, send a message:

```sh
curl -i http://localhost:8787 \
  -H 'Content-Type: application/json' \
  -d '{"id":"123"}'
```

The response is `202 Accepted`. After the batch is delivered, the Worker terminal logs `Received:` with the message body. Local testing does not require a deployed queue.

## Deployment

To run the same Worker on Cloudflare:

```sh
npx wrangler login
npx wrangler queues create jobs
npx wrangler deploy
```

Skip queue creation if `jobs` already exists. Send the same request to the deployed Worker URL to enqueue a message.

# cfqu

## Purpose

A small TypeScript library that routes Cloudflare Workers queue events by queue name.

## Specification

Install [cfqu from npm](https://www.npmjs.com/package/cfqu):

```sh
npm install cfqu
```

### Queue-only Worker

```ts
import { Qu } from "cfqu";

const qu = new Qu<Env>();

qu.on("collect", async (batch, env) => {
  for (const message of batch.messages) {
    await env.COLLECT_WORKFLOW.create({ params: message.body });
  }
});

export default qu;
```

`Env` is the bindings type generated by running `npx wrangler types` in your application, based on your Wrangler configuration. Pass this generated type to `Qu<Env>` and, when using Hono, to `Hono<{ Bindings: Env }>`. The generated types also include Workers runtime types such as `MessageBatch` and `ExecutionContext`.

### Using with Hono

Install Hono separately in your application.

```ts
import { Hono } from "hono";
import { Qu } from "cfqu";

const hono = new Hono<{ Bindings: Env }>();
const qu = new Qu<Env>();

hono.post("/jobs", async (c) => {
  await c.env.JOB_QUEUE.send({ id: "123" });
  return c.json({ accepted: true }, 202);
});

qu.on("jobs", async (batch, env) => {
  for (const message of batch.messages) {
    await env.JOB_WORKFLOW.create({ params: message.body });
  }
});

export default {
  fetch: hono.fetch,
  queue: qu.queue,
} satisfies ExportedHandler<Env>;
```

### Routing behavior

- `on(name, handler)` returns the instance so registrations can be chained.
- Queue names use exact, case-sensitive matching. Use the same name as `queues.consumers[].queue` in your Wrangler configuration.
- Registering the same name again replaces the previous handler.
- Handlers receive the original `batch`, `env`, and `ctx` arguments. Asynchronous handlers are awaited.
- Unregistered queues throw `Unknown queue: <queue name>`. Handler errors propagate to the caller.
- Message acknowledgement and retries follow Cloudflare Queues defaults. Call ack or retry methods in your handler when needed.

The package includes ESM and TypeScript declarations. Cloudflare Workers is the only supported runtime.

npm ci

```

`npm run check` builds the library, checks the usage examples' types, and runs routing tests and Workers runtime tests with Miniflare / workerd.

```

`npm pack` runs validation and creates a distribution archive.

## Deployment

### Publishing to npm

For each new release, sign in with an npm account that has permission to publish `cfqu`, then increment the version before publishing:

```sh
npm login
npm version patch
npm publish
```

Build and validation run automatically before publishing. Published version numbers cannot be reused.

### Deploying your Worker

Register a consumer in your application's Wrangler configuration. For a Worker handling `collect`, add the following to your existing `wrangler.jsonc`:

```jsonc
{
  "queues": {
    "consumers": [{ "queue": "collect" }]
  }
}
```

Configure Workflow bindings in your application as well. The Hono example also requires a `JOB_QUEUE` producer binding.

```sh
npx wrangler queues create collect
npx wrangler types
npx wrangler deploy
```

Skip queue creation if the queue already exists.
